# NVIDIA Multi Frame Generation candidate

This feature is separate from the WinGDK repair in PR #55 and depends on that
branch until it is merged. The PR, code, UI and packaging were generated by
GPT 6.1 Sol. The existing tested Game Pass prerelease remains unchanged.

The NVIDIA FG section adds **FG Multiplier** with 2x, 3x, 4x, 5x, 6x and Dynamic.
Selection skips modes unavailable on the actual GPU/driver. A 2x multiplier adds
one frame; 6x adds five. Without an external unlocker, RTX 40 remains 2x. Official NVIDIA Multi Frame
Generation and Dynamic require compatible RTX 50 hardware and driver/runtime
support. The selector uses reported SDK capabilities rather than a GPU-model
whitelist. An externally installed MFG Ada Unlock can expose higher modes on
RTX 40; it is not bundled, and that combination is qualified separately. AMD selection and its 2x route retain their existing guards.

The current Streamline 2.14.1 SDK already exposes these features. Fixed modes
are limited by `DLSSGState::numFramesToGenerateMax`. Dynamic requires
`bIsDynamicMFGSupported` and uses `DLSSGMode::eDynamic` with
`dynamicTargetFrameRate=0`, targeting the current display refresh rate. It is
not an application loop that duplicates presents or a replacement for Reflex.
See the [NVIDIA integration guide](https://github.com/NVIDIA-RTX/Streamline/blob/v2.14.1/docs/ProgrammingGuideDLSS_G.md#63-enabling-dynamic-multi-frame-generation).

## Persistence and admission

Legacy FG settings gain an optional `FrameMode` integer: 0..4 select 2x..6x,
5 selects Dynamic. An absent field remains 2x, preserving old saves. FrameMode is matched
case-insensitively because Unreal may preserve its interned spelling as
frameMode; differently cased duplicates are rejected. Runtime
capabilities and the accepted mode are returned through the FG runtime slot;
the GDK allowlist and codecs cover these fields. Consolidated settings use the
existing Single/NativeMfg strategies plus the new Dynamic strategy value 3;
existing Hybrid value 2 is unchanged. Migration preserves the multiplier.

The plain-C configuration remains 48 bytes. `generatedFrames=1..5` selects fixed
2x..6x; zero selects Dynamic. The SDK bridge checks the live device capability
before enabling a requested mode. Unsupported saved preferences suspend FG and
remain visible as unavailable, allowing selection of a supported mode. They are
not silently applied as 2x or advertised as successful.

Changes use the existing suspend/reconfigure/resume path. Frame identity,
source/guide matching, UI-alpha lifetime, startup ownership and terminal-fault
retirement guards remain in place. On the selected NVIDIA presentation route, FG Off suspends generation without
freeing its feature, so On can resume in the same process. Valid legacy NVIDIA
settings also reserve this route when starting with Off. Consolidated NVIDIA
selection reserves it only for an eligible SR/FG pairing. Missing/invalid startup
settings, provider changes and terminal fault retirement still require restart.
The experimental observed-startup mirror retains its startup-only routing.
Keeping the NVIDIA proxy while Off can retain memory and presentation overhead;
the fb6860a candidate passed a player On/Off/On trial with resumed 3x output,
zero SDK/coordinator/marker faults and no permanent feature release. The player
also verified starting with saved Off and enabling On in gameplay; new-session
SDK samples confirm 3x output without faults. No NVIDIA runtime update or driver-profile edit is
required by this candidate.

## Verification

Targeted checks cover fixed/dynamic capability limits, old and new save slots,
GDK admission, legacy migration, shared NVIDIA/AMD projection, real UI selection
and one-frame suspension during configuration changes. The source-matched
NeoRune UI compiles. Windows/Linux CI and a GPU smoke test are recorded in the
feature PR as they become available.

The case-corrected candidate ca6d3d2 was tested on RTX 4080 with the player's
external MFG Ada Unlock, HDR, DLSS Performance and Reflex. The 2x regression
reported about 80 rendered / 160 presented FPS; 3x reported 60-70 / 180-210.
The player confirmed fixed 4x, 5x and 6x output. SDK outcome samples separately
recorded 3, 4, 5 and 6 actual presentations with result/status zero.

Dynamic was selected, persisted as FrameMode 5 and accepted by the bridge;
the player reported working output. This does not yet establish adaptive pacing:
the loaded NVIDIA override uses wrapper 2.14.16.0 / provider 310.9.16.0, which
the unlocker labels general compatibility only, not release-supported Dynamic.
See the [unlocker runtime requirements](https://github.com/mavismmg/MFGAdaUnlock-RenoDx#dynamic-multi-frame-generation).
Native RTX 50 hardware and Dynamic adaptation under varying load remain unverified.
Saved-Off startup and live activation passed on fb6860a. The later 312d028 GDK
shutdown candidate passed one normal game exit with a stopped save worker and
no retained shipping process after SR/3x FG gameplay. The player reports no
noticeable performance loss with FG Off and accepts that cost as non-blocking;
instrumented overhead remains unmeasured.
A visible selector or passing synthetic capability test is not runtime proof.
