# AMD SDR Frame Generation input boundary

SDR FG is not active yet. This records the input contract needed to extend the
current HDR route. The [numeric receipt](../qualification/providers/amd-sdr-boundary-2026-10-12.json)
contains source/framework pins, primitive metadata and all exit results. No game
shader binaries, raw logs, screenshots or runtime DLLs are attached.

## Current gap

The AMD game bridge accepts HDR-shaped swapchain formats, sets the HDR creation
flag unconditionally and expects a 10-bit HUD-less world texture. The image
producer recognises the HDR compositor `0x378df900`, with separate world/UI
inputs. That is not the SDR presentation layout observed below. The menu's FG
status text also carries a generic HDR requirement; it must follow the actual
provider/output contract when SDR is implemented.

AMD requires creation flags to describe the input colour range, a matching
transfer function and display-sized colour input. Texture format alone does
not identify the colour encoding. See the [official Frame Generation API](https://gpuopen.com/manuals/fsr_sdk/techniques/frame-interpolation-api/).

## Bounded game observations

CachyOS KDE/Wayland, RTX 4080 SUPER, driver 615.78.08, CachyOS Proton SLR
11.0-20261005 and Steam build 25754144 / game 1.1.2.0. FSR Quality successfully
reconstructed 2560×1440 to 3840×2160 with runtime phase 5 and error 0. FG stayed
Off. Native HDR output was saved Off before startup. The HDR addon was held
outside the game for the plain-SDR controls and restored afterward.

An additional private Microsoft-ABI guide build records the actual ReShade
presentation colour space, indexed/non-indexed draw arguments, viewport,
scissor and blend/write-mask metadata. Geometry observation requires explicit
bounded capture; its callbacks return before locks when capture is disabled or
process termination has begun. Rendering commands and FG SDK evaluation are
unchanged by this diagnostic. The matching source compiled with the 16 KiB
stack guard; 27 related source/analyzer checks pass locally.

The loaded game's output reported **sRGB**, ReShade colour-space value 1, with
a 10-bit `R10G10B10A2_UNORM` backbuffer. A 10-bit format therefore must not be
treated as proof of HDR.

At the candidate scene/UI boundary:

| Observation | Result |
| --- | --- |
| First scene draw CRC32 | `0x088c6818` |
| Draw | Indexed; three elements, one instance |
| Viewport and scissor | Full 3840×2160 output |
| Blending | Disabled |
| Colour write mask | RGB, `0x7`; alpha is untouched |
| Subsequent UI draw CRC32 | `0x90a70e52`; blending enabled |

Descriptor/draw-order observations identify a candidate pre-UI capture boundary.
They do not prove a HUD-less pixel snapshot, generated-image quality or active
SDR FG. The untouched alpha requires an explicit snapshot policy or independent
proof that the SDK ignores it; stale backbuffer alpha must not be assumed valid.

## Shutdown controls

| Route | Held game exit | Confirmation to process gone |
| --- | --- | ---: |
| Setup main-menu exit with HDR addon, calibration pending restart | `0xc0000409` | 2.85 s |
| Restarted native HDR Off with HDR addon present | `0xc0000409` | 2.23 s |
| Original candidate SDR gameplay without HDR addon | 0 | 3.46 s |
| Private geometry diagnostic SDR gameplay without HDR addon | 0 | 4.91 s |

No sampler was installed in any of these runs. These observations preserve an
unexplained shutdown defect beyond the earlier sampler comparison. The changed
configuration, capture timing and addon presence do not establish causation.
SDK success or a closed window is not a substitute for the held process result.

Original mod files, mod preferences, renderer configuration, HDR addon and HDR
calibration values were restored. The first setup recovered two calibration
values from native before-write receipts rather than an original external-INI
byte snapshot. The later geometry transaction backed up that external INI before
changes and verified exact byte restoration. Player/account saves were not copied
or edited.

## Required implementation gate

Use an owned, current-frame post-tone-map/pre-UI snapshot with explicit colour
and alpha semantics, recording/queue identity and GPU retirement. Select SDK
colour flags and transfer from the actual output contract. Output colour or
dimension changes must stop generation, safely retire its generation resources
and create a matching context without introducing a second presentation owner.
Preserve the qualified HDR route and independent SR/latency state.

Then qualify SDR/HDR transitions, output resize, UI/moving-image parity and
ordinary shutdown on matching artifacts. Native Windows/Radeon and active
Anti-Lag 2 remain separate required checks. Published releases and the existing
Windows candidate pins are unchanged.
